03 — Technology Stack

Every tool, every role, every reason

Each technology was chosen deliberately. Do not swap components without understanding the trade-off — the stack is designed as a system.

Frontend Framework
React + Vite
Fast, component-driven UI with near-instant hot-reloads. Use functional components and hooks exclusively. Vite's build speed means you iterate in seconds, not minutes.
Frontend
State Management
Context API → Zustand
Start with React Context API for simplicity. Migrate to Zustand if state gets complex across 3+ views. Manage the multi-step pipeline state machine: Idle → Uploading → Processing → Analyzing → Done.
Frontend
Styling
Tailwind CSS
Utility-first framework. Build the enterprise legal aesthetic with responsive prefixes (sm:, md:, lg:) from day one. Never write a custom CSS file until you genuinely need to override Tailwind.
Frontend
Backend Runtime
Node.js + Express
The central orchestrator. Receives all user data, calls OCR, sends text to HF, formats and returns responses. Acts as a secure API proxy — your credentials never reach the client.
Backend
File Handling
Multer + pdf-parse
Multer handles multipart binary uploads (images, PDFs). pdf-parse extracts clean text from digital PDFs page by page. Together they handle every non-text input type in Phase 2 and 3.
Backend
Validation
Zod
Define strict schemas for every API payload. Reject invalid file types, enforce text length limits, and catch malformed requests before they reach your AI pipeline. Prevents silent failures.
Backend
Image Pre-processing
OpenCV.js / Sharp.js
Deskew, greyscale, normalise contrast, and sharpen edges before OCR. This single pre-processing step lifts Tesseract accuracy from ~65% on real photos to 90%+. Non-optional for the CamScanner feature.
OCR Pipeline
OCR — Free Tier
Tesseract.js
JavaScript port of Google's Tesseract. Runs in Node.js, free, offline-capable, 100+ language support. Primary OCR engine. Route to Textract only when Tesseract confidence falls below 70%.
OCR Pipeline
OCR — Production
AWS Textract
Production-grade OCR with table and form detection. Handles dense multi-column legal documents that defeat Tesseract. 1,000 free pages/month. Fallback only — keeps costs near zero in development.
OCR Pipeline
AI Classifier (MVP)
BART-Large-MNLI
Zero-shot classification via Hugging Face Inference API. Define labels (Privacy Risk, Hidden Fee, Liability, Arbitration Clause) and the model scores every text chunk. No training data required — the core enabler of the MVP.
AI / ML
AI Classifier (Scale)
Legal-BERT
Pre-trained on legal case law and contracts. Understands "legalese" far better than a general model. Upgrade path from BART-MNLI for Phase 3 when you need clause-level precision on professional contracts.
AI / ML
Client-Side Security
DOMPurify + Immediate Deletion
Sanitize all text inputs client-side with DOMPurify before sending to backend. Implement server-side immediate deletion of uploaded images and PDFs after processing — never persist user documents.
Security
PDF Export
jsPDF
Generate downloadable analysis reports from the frontend. Render the Trust Score, summary table, and full risk card details into a professional PDF the user can share with a lawyer or keep on file.
Frontend
Database (Phase 3)
Supabase (PostgreSQL)
Hosted Postgres with a REST API and auth built in. Store anonymized Trust Scores per company for the community database. Free tier handles the entire Phase 3 build with room to spare.
Backend
Hosting
Vercel + Render
Vercel for the React frontend (zero-config deployment, global CDN). Render or DigitalOcean for the Express backend. Connect both to GitHub for automatic deploys on every push to main.
DevOps
⚠ Scaling Tip — When to upgrade from BART to Legal-BERT
BART-MNLI is your MVP workhorse. Switch to Legal-BERT in Phase 3 when you start handling professional contracts (NDAs, leases, employment agreements). BART understands language broadly; Legal-BERT understands the specific vocabulary, sentence structures, and nuance of legal documents — the difference between "best efforts" and "reasonable efforts" in a contract matters enormously, and Legal-BERT knows that. The migration is a single model-endpoint swap in your backend config.
04 — Execution Roadmap
01
Digital MVP
Weeks 1 – 3

The Digital MVP

Ship a working web-based T&C analyzer — paste text, receive color-coded risk cards — that real users can access by Week 3.

  • W1
    Infrastructure & Project Skeleton Scaffold Vite + React (client/) and Express (server/) in a monorepo. Configure CORS, connect with Axios, wire up .env for secrets. Set up GitHub with main/dev/feature-* branches. Add ESLint + Prettier with format-on-save. Push a health-check endpoint that returns {"status":"ok"} and confirm the frontend can call it. Do not write application logic until both services communicate cleanly.
  • W2
    Hugging Face AI Bridge Create POST /api/analyze on Express. Write a text-chunking utility that splits input into ~300-word segments with 50-word overlaps (prevents cutting mid-clause). Call the BART-Large-MNLI Inference API with labels: ["Privacy Risk", "Hidden Fee", "Auto-Renewal Trap", "Liability Waiver", "Arbitration Clause", "Fair"]. Build and test the entire chain in Postman before touching the frontend — this is backend-only week. Pro-tip: Save your Postman collection as a JSON file in the repo under /docs/api-tests.json. Future collaborators will thank you.
  • W3
    Analysis Dashboard UI Build the complete React dashboard: textarea with character counter, "Analyze" button with multi-state loading spinner, and a results zone rendering RiskCard components. Map HF scores to severity — above 0.85 = Red, 0.60–0.85 = Amber, below 0.60 = Blue. Add a Summary Bar showing total flag counts. Handle API errors gracefully (rate limits, timeouts). Deploy to Vercel + Render. Share with 5 people for live feedback before Phase 2.
02
The Vision Layer
Weeks 4 – 6

The Vision Layer

Bring ClearSight into the physical world — photograph a paper contract, get an AI analysis — while hardening the platform with security and privacy controls.

  • W4
    OCR Engine Integration Add a "Scan Document" tab with react-dropzone (drag-and-drop, accepts JPG/PNG/WEBP, max 10MB). On the backend, integrate Tesseract.js via Multer. Create POST /api/ocr that returns extracted text + confidence scores. On mobile, use input type="file" capture="environment" to open the camera directly. Log all sub-70% confidence requests for quality monitoring.
  • W5
    Image Pre-processing Pipeline Before OCR, run every image through Sharp.js: auto-rotate (EXIF correction), convert to greyscale, normalise contrast, apply unsharp-mask sharpening, output as lossless PNG. Add a basic crop/rotate UI control in React so users can straighten skewed photos before submission. Build the end-to-end route POST /api/scan-and-analyze: Sharp → Tesseract → chunk → BART-MNLI → results. If Tesseract confidence is below 70%, auto-fallback to AWS Textract silently. OpenCV.js note: For the browser-side crop/rotate tool, OpenCV.js works but is heavy (8MB+). Favour Sharp.js server-side for all processing — it's faster, lighter, and easier to debug in Node.
  • W6
    Security & Privacy Hardening Implement client-side input sanitization with DOMPurify on all text fields. Server-side: delete all uploaded images and PDFs from disk immediately after processing completes — never persist user documents. Add rate limiting to all routes (express-rate-limit: 20 req/min per IP). Add the mandatory first-time Legal Disclaimer modal in React (stored in localStorage so it only shows once). Add HTTPS enforcement and security headers via Helmet.js.
03
The Intelligence Layer
Weeks 7 – 10

The Intelligence Layer

Evolve from a T&C scanner into a full contract intelligence platform — with contextual playbooks, a Trust Score engine, PDF support, and community data.

  • W7
    PDF Parsing & Contract-Type Detection Add PDF upload support via pdf-parse. Extract text per page; route image-based PDF pages through the OCR pipeline. Add a preliminary BART-MNLI classification step that detects the document type (NDA, Lease Agreement, Employment Contract, Service Agreement, General T&C) before the main analysis. This drives the Contextual Playbook selection in Week 8.
  • W8
    Contextual Playbooks Store label sets as JSON config files — one per contract type. Lease: ["Security Deposit Terms", "Eviction Clause", "Landlord Entry Rights", "Maintenance Responsibility"]. NDA: ["Broad Disclosure Scope", "Perpetual Confidentiality", "IP Assignment"]. Employment: ["Non-Compete Scope", "At-Will Termination", "IP Ownership"]. The backend loads the correct playbook based on the contract-type detection result. Add a manual override dropdown in the UI for user correction. This is the feature that separates ClearSight from every competitor. Domain-specific label sets mean your accuracy on professional contracts will dramatically exceed any general-purpose tool.
  • W9
    The Trust Score Engine Build the Trust Index algorithm: start at 100, subtract weighted penalty points per flag — Red = −15 pts, Amber = −5 pts, floored at 0. Display as an animated circular gauge with color transitions: red (0–40), amber (41–70), green (71–100). Add a company name input to the analysis flow. Persist anonymized scores to Supabase. Build a public "Company Lookup" page — search any company name and see its aggregated Trust Index from all community analyses.
  • W10
    One-Click Export & Final Polish Implement jsPDF export: a professional report with document metadata, Trust Score gauge, severity summary table, and all risk cards with plain-language explanations. Add "What this means for you" copy for every label in the playbook library. Run a final round of user testing across desktop and mobile. Write a README documenting setup, architecture, and every API route. This is your portfolio submission — treat the documentation as seriously as the code.
